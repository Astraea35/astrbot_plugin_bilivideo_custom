# 下载断连与订阅恢复

遇到网页或 JSON 元数据获取阶段的 TLS EOF、连接重置、超时，下载器等待 1、2 秒额外重试两次。证书校验失败、403/412 与 FFmpeg 转换失败不进入此重试。音频传输使用 yt-dlp 自己的两次重试，不再叠加整个下载重试。

订阅原有的整流程 5、10、15 秒重试保留。网络失败耗尽后，第一次失败通知发送成功才记录待恢复状态，保留原 `last_bvid`；之后按 5 分钟、15 分钟、60 分钟的间隔，最多执行三轮恢复。实际执行时间取决于订阅扫描进度，不保证精确到点。

同一视频不重复发送失败通知。总结成功并完整发送后才更新 `last_bvid` 并清除待恢复状态。恢复状态写入订阅 JSON，可跨插件重载保留；失败通知本身没发成功时保持原状态。

此补偿只跟踪每个 UP 的最新视频；UP 发布更新视频时优先处理新视频，不积压旧视频。此前已写入 `last_bvid` 的历史失败不会自动迁移，需单独重做。非网络错误仍沿用三次即时重试后发一次最终通知的原有行为。

这是对间歇断连的容错修复，不能据此声称运营商或 B 站接入链路已经恢复。全程保留 HTTPS 证书验证，不修改代理、DNS、TUN 或主机网络参数。
