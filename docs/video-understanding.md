# 视频理解

默认仍为字幕总结。新增能力只影响视频总结，不改变酷安、知乎或动态摘要的模型配置。

## 开启方式

重载插件后，在 AstrBot 插件配置的“视频理解（可选）”栏目，或插件控制台“总结生成”中设置：

| 总结依据 | 行为 | 所需能力 |
| --- | --- | --- |
| 字幕 / 音频转写 | 保持原有字幕优先、失败后 ASR 的流程 | 文本输入 |
| 字幕＋画面 | 下载视频，模型按需补看时间点或局部画面；也可选择固定均匀抽帧 | 图片输入 |
| Gemini 原生视频 | 将视频及音轨交给模型理解 | 对应模型、渠道的视频输入接口 |

视频理解模型提供者留空时复用主总结模型，也可选择 AstrBot 已配置的另一个模型。模型名称和生成参数统一使用该提供者在 AstrBot 中的配置，插件不再提供模型名称覆盖设置；无需按 GPT、DeepSeek 或 Gemini 品牌分别设置抽帧流程。是否支持图片，取决于实际型号与所选渠道。

字幕不存在或不可靠时，画面模式可以只根据抽样图片生成总结，并明确标注没有可用字幕。抽样不能保证覆盖全部动作、字幕或短暂出现的内容。视频模式会下载视频，耗时、流量和图片输入费用通常高于仅处理已有字幕。

## 原生视频与反代

原生视频只使用所选 AstrBot Gemini 原生提供者的接口、密钥、模型、代理与自定义请求头，插件不再提供独立的接口地址和密钥设置。仅凭 OpenAI 兼容接口里的模型名称含有 `gemini`，不能认定原生视频或 Agentic 可用；Responses 接口同样不能证明 Gemini 原生接口已经开放。

如需使用反代，请在 AstrBot 中配置 Gemini 原生提供者的接口基址、密钥和代理，再在插件中选择该提供者。接口基址允许带 `/v1beta`，不能填 `/chat/completions` 或 `/responses`；不要自行假定反代一定开放原生视频路由。

- 切换服务时在 AstrBot 中选择或配置对应提供者，插件统一使用该提供者的连接与认证配置。
- 优先使用 Gemini Files API 上传、等待预处理，再调用模型。上传接口不支持时，开启回退的小视频可以使用内联输入；原始视频最多 12 MiB，以控制 Base64 编码后的请求大小。
- 更大的视频需要可用的 Files API；如果反代只支持图片输入，可使用“字幕＋抽样画面”。
- 上传会使用所选 AstrBot 提供者的接口地址。成功、失败、取消或超时后都会尝试删除已取得文件名的远端文件；删除失败会记录日志。最终保留规则仍由渠道决定。如果上传响应中断且未取得文件名，插件无法定位该远端文件。
- 本地视频与抽帧文件放在每次请求独立的临时目录中，请求结束后清理；下载线程取消后会先等待其停止，再删除目录。

## 模型按需补看（默认画面策略）

画面模式默认先提供 12 张低分辨率预览（宽度不超过 640 像素），结合均匀时间点与场景变化候选。模型根据字幕和预览，决定是否请求某个时间点的完整高清画面，或该画面的局部区域，以读取跑分表、温度曲线、参数对比等信息。局部坐标始终相对原始完整画面。

每轮最多请求 12 张，默认最多补看 3 轮，整次最多使用 48 张图片。预览、高清帧和局部图都占用这一总预算；信息足够时模型可提前结束，预算不是每次必须使用的张数。图片总预算可设 1～96，预览数量会自动限制在总预算内，补看最多 6 轮。可切换为“固定均匀抽帧”，此时图片预算表示固定取样数量，不调用补看规划。

此功能复用 AstrBot 的图片聊天接口，以 JSON 表达补看请求，不要求渠道开放原生工具调用。模型或反代不支持该流程、输出格式不正确、没有有效的新请求或规划超时，会根据已经取得的图片生成总结并提示补看未完成。最后总结失败时，按原有回退开关决定是否使用字幕总结。

视频下载高度默认上限 1080p，补看及均匀抽帧宽度上限默认 1280 像素；不会放大低清来源，局部图先裁剪再缩放。实际可用画质取决于平台权限和源视频。场景检测最多扫描 45 秒、保留 256 个变化候选；检测不可用时仍提供均匀时间点预览。它不能保证发现所有短暂图表或静态画面里的数值变化。

视频本身长度上限默认为 60 分钟（3600 秒），视频大小上限为 256 MiB，整次总结请求限时默认为 600 秒（10 分钟）。三者分别限制源视频长度、下载/上传大小和请求总耗时，并非 token 预算。阶段调用与规划还有独立限时，可能更早结束；已显式保存的旧配置值继续保留，不会被新版默认值覆盖。如仍为 8 张/480p，可在设置中调整为上面的建议值。

规划和最后总结会重新传入已取得的图片，以便模型保留证据。48 张表示提取的图片总数，**不是累计计费图片数或 token 上限**；重复传图、多轮请求、源画质提升可能增加费用。结果标注实际图片数和补看轮数；达到预算后明确按已有证据总结，不能声称完整检查了全部测评数据。

按需补看与 Gemini 原生 Agentic 是两套不同流程。原生视频成功时不使用插件的预览、图片数或补看轮数限制；只有回退到画面模式时才应用这些设置。下载高度、视频大小与时长限制仍适用于两种视频路径。

## 自动、Static 与 Agentic

- **自动**：当前入口的任务是覆盖整段视频的总结，因此选择 Static。不会仅凭视频较长就自动启用 Agentic。
- **Static**：默认使用 generateContent；也可以手动指定 Interactions。它和插件自己的稀疏抽帧总结是两条不同的路径。
- **Agentic**：使用 Interactions，并在视频输入上发送 `processing: "agentic"`。必须由实际型号与渠道同时支持。

Gemini 官方建议整段、广泛的总结优先考虑 Static；Agentic 更适合长视频中的定向查找。Agentic 可能额外产生思考和工具使用开销，插件不承诺固定节省比例。需要比较费用时，应同时查看输入、输出、思考、工具使用与渠道价格。

Agentic 返回结果里有 `processing_call` 时才记为已确认；没有对应记录时标记为“Agentic（渠道未确认）”，不会把请求成功当成已证实智能模式生效。

## 回退与缓存

“视频理解失败时回退”默认开启：

1. 请求的原生处理模式被接口拒绝时，尝试原生 Static。
2. 原生视频不可用时，尝试字幕＋抽样画面。
3. 画面下载、抽取或视觉调用失败时，尝试原有字幕 / ASR 总结。

关闭后直接报告失败。认证失败、限流等不会在原生接口内部反复切换请求协议；外层回退仍可利用主总结模型已配置的备用模型。

结果会标明实际使用的依据与回退情况。回退结果不保存为长期总结缓存，以便渠道恢复后重新尝试。总结缓存包含模型身份、总结方式、处理模式、画面数量及提示风格等设置；旧版缓存不会直接冒充新模式结果。

原生视频接口的 token 使用信息（若渠道返回）保存在结果的 `usage` 元数据中。图片路径记录提取图片数、预览数、补看轮数与停止原因，暂不单独统计 token；渠道计费仍以其实际账单为准。同步请求取消或超时不保证渠道的远端推理立即停止，插件只保证本地取消与清理流程。

## 验证范围

自动化测试使用本机 HTTP 服务模拟 Gemini 原生接口，覆盖请求格式、上传、预处理、模式回退、密钥隔离、超时与清理；FFmpeg 测试使用本地生成的测试视频。没有把真实用户视频上传到外部模型。

反重力或其他反代实际是否开放原生视频、文件上传、Interactions，需要其具体地址与真实响应来确认。上述模拟测试通过不等同于这些渠道均可用，也不等同于真实模型总结质量或 token 节省已实测。
